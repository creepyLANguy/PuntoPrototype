# Firestore data model

This is an implementation reference. These paths are not part of the public API contract and may change without changing public response schemas.

| Path | Role |
|---|---|
| `courts/{courtId}` | Court configuration and match generation |
| `courts/{courtId}/score/current` | Materialized authoritative current score |
| `courts/{courtId}/events/{eventId}` | Append-only scoring/device event history |
| `courts/{courtId}/scoreCheckpoints/{id}` | Replay accelerators |
| `courts/{courtId}/archive/{isoTimestamp}/events/{eventId}` | Archived pre-reset events |
| `devices/{deviceId}` | Hardware binding/configuration |

## Court document

Known fields include `name`, `status`, `password`, `teamNames`, `playerNames`, `scoringMode`, `scoringOptions`, and `scoreVersion`.

Passwords and device credentials must not be exposed through public API responses.

## Current score

Contains the materialized A/B points, games, sets and total points plus completed-set information, tiebreak/deuce state, last-event metadata and timestamps. It is derived state and can be rebuilt from events.

## Event document

Known fields include `eventType`, `createdBy`, `createdAt`, `scoreVersion`, and device binding metadata such as `actorDeviceId`, `targetCourtId`, `sourceCourtId`, and `registeringDeviceId` where applicable.

### Required production additions

Mutation events should also have:

- immutable `eventId` generated by the originating device/client;
- authentication credential metadata sufficient for server verification without storing plaintext secrets;
- canonical request hash/signature metadata;
- server receipt timestamp;
- deduplication/acceptance state where needed.

Never use a client-provided timestamp as the authoritative ordering clock without preserving server receipt time as well.

## Checkpoints

Checkpoints are optimizations. They must be disposable and reproducible from the event log. Reset and option changes must invalidate/rebuild affected checkpoints.

## Archives

Reset archives must preserve enough metadata to reproduce/debug the prior match without exposing credentials. Retention and deletion policy should be defined before production launch.

## Indexes

Queries should be reviewed against `firestore.indexes.json`. If a new query requires a composite index, add it explicitly and deploy it consistently to staging and production.
